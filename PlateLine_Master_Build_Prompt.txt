I am building **PlateLine**, a privacy-first, local-first mobile app (Android-first) for a hackathon. If a free tier runs out, degrade gracefully — never fake functionality.

## WHAT PLATELINE IS
A meal-and-glucose journal that puts home-cooked meals, glucose readings, and therapy (pill/insulin) timing on ONE chronological timeline. Optional AI meal-photo analysis acts as a **"Draft-Maker"**: it proposes food items and nutrition MIN–MAX ranges; the user reviews, corrects, and must explicitly Accept. AI is never required to log anything. Formerly "Glucose Journal."

## TARGET USER
Adults (35–65) with Type 2 diabetes (or their caregivers) who currently log readings in a notebook, eat predominantly home-cooked multi-ingredient meals that barcode apps fail on, own a mid-range Android phone, and are cost-sensitive and privacy-conscious.

## HARD RULES — violation means the build failed
1. All user data stays in on-device SQLite. No cloud database, no accounts, no sync.
2. Glucose values and history NEVER leave the device. The AI proxy receives ONLY a meal photo, and ONLY after explicit in-app consent.
3. API keys exist ONLY in server-side env vars (Cloudflare Worker secret). Never in app code, never in the repo, never logged.
4. NOT A MEDICAL DEVICE. Never diagnose, never recommend insulin/medication/treatment, never predict glucose from a photo, never say a meal "caused" a reading. Use only: "recorded near", "appeared after", "recorded X min after: [meal]".
5. AI nutrition values are estimates: always show MIN–MAX ranges, always label "AI estimate", always allow rename/adjust/add/remove, and require Accept before saving. Track source per value: 'ai' | 'user' | 'demo'. Show a small badge when user-edited.
6. Store timestamps as LOCAL date-time strings. No UTC conversion. Prove stability: save, reload, edit a non-time field, confirm timestamp unchanged.
7. One glucose unit throughout (default mg/dL, configurable in Settings), clearly labelled everywhere. Never silently mix units.
8. Reading context is optional: Fasting / Before meal / After meal / Other / Prefer not to specify. Save null if unset; display "Context not specified". NEVER infer context from time, photo, or glucose value.
9. Pattern cards appear ONLY when a keyword-normalized meal has 3+ pairs (readings 1–3h after the meal). Every card MUST include verbatim: "These are recorded associations only. Many factors affect glucose, and this does not show that a meal caused a reading." No advice, no prediction. Otherwise show "Not enough data yet (need 3+ matching entries)."
10. Every report and the app itself carry the footer: "PlateLine is a journaling tool, not a medical device."
11. Use ONLY fictional demo data. Add a "Load demo data" button producing 5 days of records, some AI-style estimates labelled "Demo sample", enough repeated meals to trigger exactly one pattern card, plus "Remove demo data".
12. Work in small verifiable steps. After each step: run the app, check Metro/console logs, and tell me EXACTLY what you tested. Never claim something works without verifying it.
13. Do not rebuild working parts; make minimal, focused diffs.
14. If AI is unavailable or quota is exhausted, ship manual entry with a clearly labelled "AI analysis unavailable" state. NEVER fake analysis results.

## DATA MODEL (SQLite tables)
- readings: id, value, unit, recordedAt, context(nullable), notes, createdAt, updatedAt
- meals: id, recordedAt, description, photoPath(nullable), nutrition{calories,carbs,protein,fat,fibre} each{min,max,source}, therapyNotes(nullable), analysisStatus, createdAt, updatedAt
- photos: key, filePath, blob (<=1280px)
- analyses: id, mealId, items[{name,portion,confidence}], uncertaintyNotes, model, analysedAt, acceptedByUser
- settings: key, value (unit, targetRange, aiConsentGiven, language)

## SCREENS & NAV (bottom tabs: Timeline | Add | Chart | Report | Settings)
1. **Add — Quick Reading (<20s):** value required with friendly range validation; date/time pre-filled with current local time, editable, NOT reset by other fields; optional context; optional notes; edit preserves timestamp unless user changes it; delete with confirmation.
2. **Add — Meal Log:** same timestamp rules; optional photo (reject non-images, downscale to 1280px, handle permission/oversize errors gracefully); description; optional manual nutrition (source 'user'); optional therapy notes (pill/insulin timing); edit and delete.
3. **Analyse Meal (on Meal Log, only when photo exists):** first-use consent dialog (plain language: only the photo is sent, who receives it, glucose data never sent), consent saved in settings, withdrawable in Settings; loading state + cancel + 20s timeout; editable review card (items, portions, min–max ranges labelled "AI estimate", uncertainty notes, Add missing / Remove false / Accept / Edit / Discard); nothing saves until Accept; failure shows "AI analysis unavailable" and keeps manual entry working.
4. **Timeline:** reverse-chronological, grouped by day, meals + readings together; each reading shows value, unit, context ("Context not specified" if null), and if a meal exists within the prior 4h a neutral line "Recorded 95 min after: Dal and rice"; meals show thumbnail, description, nutrition with 'AI estimate'/'Your entry' labels; filters: date range, readings only, meals only; helpful empty state; NO causal wording anywhere.
5. **Chart:** glucose line, 7/14/30-day selector, target-range band from Settings labelled "your target range", meal markers with description tooltips, honest rendering of gaps and single points, no interpretation text.
6. **Report:** date-range selector; summary (period, count, min/max/average labelled as simple statistics), chart, readings table with context/notes, meals table with nutrition (labelled estimate/user-entered); expo-print A4 PDF with disclaimer footer; share via expo-sharing; JSON export (photos base64) and import (validate schema, preview, merge-or-replace choice) in Settings.
7. **Settings:** unit, target range, AI consent toggle, plain-language Privacy section (data stays in this phone's app storage; uninstalling deletes it; AI sends only the meal photo after consent; use export as backup), backup reminder, "Delete all my data" with TYPED confirmation; first-run welcome screen with the medical disclaimer.

## AI PROXY SPEC (Cloudflare Worker, free tier)
